# Безопасность мини-пресетов (коннекторов)

Краткие обязательные правила для репозитория [Extella-connectors](https://github.com/progprogect/Extella-connectors) и экспертов Extella.

## Секреты и KV

- **Не** вставлять API-ключи, токены, пароли, connection strings в **концепты**, **README**, **issues**, **логи агента**.
- Секреты — только в **Extella KV** (`api/kv/set`) или в секретах хостинга OAuth-брокера.
- Поле `description` у KV должно быть **нейтральным** (для семантического поиска), без значений секретов.

## Stripe

- На сервере и в экспертах использовать **Secret key** или **restricted keys** с минимальными правами.
- **Publishable key** не использовать для привилегированных операций.
- **Webhook signing secret** хранить отдельно от API-ключа; проверять подпись заголовка Stripe на входящих webhook-запросах (если реализуете приём).

## Custom REST и Custom MCP

- **SSRF:** универсальный прокси-эксперт не должен принимать произвольный URL от недоверенного пользователя без **allowlist** хостов или без статической конфигурации `base_url` в KV.
- Не следовать редиректам на внутренние сети (`169.254.x.x`, `10.x`, metadata IP) — отключить или ограничить в HTTP-клиенте.
- Таймауты и лимиты размера ответа обязательны.

## OAuth

- Использовать **PKCE** для public clients.
- Параметр `state` обязателен для защиты от CSRF.
- `client_secret` брокера не попадает в клиентский JS.

## Логи и PII

- Не логировать полные тела ответов провайдеров, если они могут содержать персональные данные.
- Маскировать секреты в `execution_log` (печатать только `***` или последние 4 символа по политике продукта).

## Соответствие ToS провайдеров

- Не предлагать пользователю **передачу логина/пароля** к третьим сервисам как основной путь; предпочитать OAuth и официальные API-ключи.
